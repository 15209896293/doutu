# 豆图 · AI 抠图方案评估（v0.6）

> 背景：图片背景非纯色/有杂物时，启发式「自动提取主体」效果有限。
> 本评估对比三种方案，给出是否引入 AI 抠图、以及引入哪一个的结论。
> 状态：评估完成，暂不落地原生插件（见结论）。

---

## 01 约束（先立边界）

| 约束 | 说明 |
|------|------|
| 本地优先 | 图片不上传，抠图必须在设备端完成 |
| 包体 ≤ 25MB | dev-plan 硬约束，APK 当前 ~19.5MB |
| 零额外原生依赖倾向 | 项目一直避免原生插件（裁剪/算法全部纯 Dart） |
| **Web 版共存** | v0.6 正在做 Web 版；**原生插件会破坏 Web 编译**，必须与 Web 版隔离 |
| 无法真机验证 | 本机无安卓设备/模拟器，引入插件后无法实测质量与崩溃风险 |

## 02 方案对比

| 维度 | local_rembg（U2-Net） | Google ML Kit 主体分割 | 现状启发式（已实现） |
|------|----------------------|------------------------|----------------------|
| 类型 | 原生插件 + 模型 | 原生插件 + Play Services | 纯 Dart，零依赖 |
| 抠图质量 | 高（语义分割，复杂背景好） | 高（同样语义分割） | 中（仅适合背景近纯色/渐变） |
| 模型体积 | u2netp ≈ 9MB / u2net ≈ 170MB | 走 Play Services 模型按需下载 | 0 |
| 包体影响 | +9MB 以上 | 依赖 Google Play 服务（国内机型兼容差） | 0 |
| 离线 | ✅ 完全离线 | ⚠️ 依赖 Play 服务版本/首次下载 | ✅ |
| 国内可用性 | ✅ | ❌ 国内安卓无 GMS，基本不可用 | ✅ |
| Web 支持 | ❌ 仅 Android/iOS | ❌ 仅 Android/iOS | ✅ 纯 Dart 可跑 Web |
| 实现成本 | 中（插件接入 + 模型资源 + 平台配置） | 中高 | 已实现 |
| 风险 | 未在本机真机验证；可能引入崩溃/包体超标 | 国内不可用，风险最高 | 无 |

## 03 结论与建议

### 建议：**现阶段不引入 AI 抠图原生插件，保持启发式方案**

理由（按优先级）：

1. **Web 版是第一优先级**：local_rembg / ML Kit 都是原生插件，会让 Web 版失去"单代码库"优势；且 ML Kit 依赖 Google Play 服务，**国内安卓基本不可用**（与目标市场直接冲突）。
2. **包体约束**：u2netp 模型 +9MB，直接逼近 25MB 红线；u2net 完全不可行。
3. **无法真机验证**：引入插件却无法实测，等于把一个不确定的崩溃源带进核心流程（此前刚修过启动闪退）。
4. **启发式已覆盖主场景**：纯色/渐变背景 + 主体清晰（大多数拼豆照片场景）效果足够；复杂背景可用手动裁剪兜底。

### 什么时候再考虑

- 出现明确证据：真实用户反馈"背景太复杂、自动框选不准"比例显著（埋点/反馈）；
- 且 Web 版稳定、包体预算允许（比如拆"轻量版/完整版"渠道）；
- 届时首选 **local_rembg（u2netp）**，以"可选按钮 + 失败回退启发式"方式接入，并做真机回归。

### 当前可做的低成本增强（替代 AI）

1. **多背景色聚类增强**：目前背景候选最多 2 色；对"双层背景"（如渐变+杂物）可提到 3 色并降低 ΔE 阈值自适应。
2. **连通域主体过滤**：对 flood-fill 后的大块非背景区域做面积过滤，剔除远处小杂物（提升包围盒精度）。
3. 这些已在 `subject_detector.dart` 内可增量实现，零风险。
