# v0.9 试用版方案（Supabase 激活后端 · 24h 试用 · 激活码解锁）

> 需求：打包一个**试用版**（试用 24 小时）；生成若干**测试码**，输入后获得对应期限；
> 防止「删了重新下载继续使用」。
> 决策（用户确认）：后端用 **Supabase**；到期后**全部锁定**（只显示激活页）。

---

## 1. 产品设计

### 1.1 试用版 = 独立应用

- 试用版 `applicationId = com.doutu.doutu.trial`（与正式版 `com.doutu.doutu` 不同，
  两版可共存安装，正式版不受试用逻辑影响）。
- 同一套代码，用 `--dart-define=TRIAL_MODE=true` 编译启用试用逻辑；正式版不编译该逻辑。

### 1.2 试用状态机

```
首启（TRIAL_MODE）
  → 本地无记录：开始 24h 试用（记录 installAt=now，联网注册设备）
  → 本地有记录：读到期时间
       ├─ 未到期 → 正常使用，剩余时间显示在设置/首页角标
       ├─ 已到期（试用到期 & 未激活）→ 全屏锁定时：只显示激活页
       └─ 已激活 → 到期时间 = 激活到期；未到 → 正常；已到 → 锁（需再激活）
解锁：输入激活码 → Supabase 验证（一次性、计次）→ 返回时长 → 本地记录激活到期
```

### 1.3 时间防回拨

- 本地持久化 `lastSeenAt`：每次启动/前台，若系统时间 < lastSeenAt → 判定时间被回拨，
  按 lastSeenAt 继续计时（试用时长不会被"改时间"延长）。
- 服务器时间戳为准（激活/试用由服务器签发）。

## 2. 防重置设计（重要：分层 + 诚实的平台限制）

| 层 | 机制 | 防什么 |
|----|------|--------|
| L1 | **激活码一次性 + 限量**：服务器 `codes` 表记录 `max_uses/used_count`，码用过即废 | 防「一个测试码无限传播/重复激活」——这是最实际的盗用路径 |
| L2 | **设备表**：`devices(fingerprint, trial_started_at, activated_until)`，同一指纹只发一次试用、续期累计 | 同一安装周期内清数据/重装后若指纹可识别则继续过期 |
| L3 | **Android Auto Backup**（系统默认开启）：试用/激活状态存 SharedPreferences 自动云备份，重装后恢复 → 过期状态延续 | 覆盖最常见的「卸载重装」路径（用户不关备份时） |
| L4 | **诚实的平台限制**：Android 8+ 卸载重装后 `ANDROID_ID` 会变，**平台禁止稳定跨重装设备标识**（IMEI 等需特权），因此纯指纹方案无法 100% 识别"同一台设备重装"。若需绝对防重置 → 只能登录账号（本方案不采用，保持无账号） | 说明文档向用户明示 |

> 实际效果：激活码无法复用、重装后试用不自动续期（云备份恢复时），
> 恶意"清数据/关备份+重装"可再次获得 24h 试用 —— 行业通用做法，Apple/Google 同样受此限制。

## 3. Supabase 架构

### 3.1 表结构（SQL，管理员执行）

```sql
-- 设备（试用与激活状态）
create table public.devices (
  fingerprint   text primary key,          -- 设备指纹（ANDROID_ID + 型号哈希）
  trial_started_at timestamptz not null default now(),
  activated_until  timestamptz,            -- null = 未激活
  created_at    timestamptz default now(),
  updated_at    timestamptz default now()
);
alter table public.devices enable row level security;

-- 激活码（一次性/限量）
create table public.codes (
  code          text primary key,          -- 如 DOU7D-XXXX-XXXX
  duration_days int not null,              -- 7/30/90/3650(永久)
  max_uses      int not null default 1,
  used_count    int not null default 0,
  note          text,
  created_at    timestamptz default now()
);
alter table public.codes enable row level security;

-- RLS：客户端一律禁止直读（防泄码），只允许 Edge Function（service_role）读写
```

### 3.2 Edge Function（Deno/TS，`supabase/functions/activate/index.ts`）

客户端只调两个函数，**不直接暴露数据表**：

| 端点 | 入参 | 出参 | 逻辑 |
|------|------|------|------|
| `POST /activate` | `{code, fingerprint}` | `{ok, durationDays, activatedUntil, trialExpiresAt}` | 校验码存在且 `used_count < max_uses`；更新码计数；设备行：`activated_until = max(now, 原值) + duration`；返回 |
| `POST /device` | `{fingerprint}` | `{trialStartedAt, trialExpiresAt, activatedUntil}` | 设备不存在 → 建行（试用开始）；存在 → 返回原状态（重装/清数据后联网即恢复 → 试用不重置） |

> Edge Function 用 `service_role` 密钥操作数据库，RLS 不放行匿名直读。

### 3.3 测试码

| 码 | 时长 | 限用次数 | 用途 |
|----|------|----------|------|
| `DOU7D-XXXX-XXXX` | 7 天 | 1（或 10 便于测试） | 体验 |
| `DOU30D-XXXX-XXXX` | 30 天 | 1 | 深度体验 |
| `DOU90D-XXXX-XXXX` | 90 天 | 1 | 忠实用户 |
| `DOUPERM-XXXX-XXXX` | 永久 | 1 | 内部/答谢 |

生成脚本 `tools/gen_trial_codes.dart` 输出 SQL INSERT（直接贴 Supabase SQL Editor 执行）。

## 4. 客户端实现

- `lib/core/license/license_state.dart`：试用/激活状态模型 + 到期计算 + 时间回拨检测（纯 Dart，可单测）
- `lib/core/license/license_gateway.dart`：http 调 Supabase Edge Function（仅 TRIAL_MODE 编译）
- `lib/core/license/license_controller.dart`：状态机 + 持久化（复用 AppStorage JSON）
- 激活页 UI：全屏锁定（App 不出主页），显示剩余试用/已到期、输入激活码、激活结果反馈
- 打包：`tools/build_apk.ps1` 增加 `-Trial` 参数（`--dart-define=TRIAL_MODE=true`），
  `android/app/build.gradle` 读 dart-define 追加 `.trial` applicationId

## 5. 交付物

1. 试用版 APK：`豆图_试用版_v0.8.0_*.apk`（独立 applicationId，可与正式版共存）
2. 部署包：`supabase/schema.sql` + `supabase/functions/activate/index.ts`（用户贴到 Supabase）
3. 测试码：生成后由用户执行 SQL 录入 Supabase
4. 本文档 + 使用说明

## 6. 验收

- 新装试用版：开始 24h 试用，倒计时显示
- 到期：全屏锁，只能输入激活码
- 输入测试码：解锁对应时长；同一码第二次使用被拒
- 清数据/重装（开启云备份）：试用不重置；激活状态恢复
- 正式版 v0.8.0：不受影响，全功能
