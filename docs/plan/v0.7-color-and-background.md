# v0.7 迭代：色差与背景误识别的根因拆解 + 修改方案

> 背景：用户反馈「生成的拼豆图纸有色差」「部分背景也被识别成拼豆」。
> 本文先拆解 [pixel-beads.com](https://www.pixel-beads.com/zh)（拼豆图纸生成器标杆站）的处理与设计
> （逆向其前端产物 + 公开技术资料），再对照本项目 `lib/core/` 现状给出可落地的修改方案。

## 一、pixel-beads.com 是怎么做的

### 1.1 产品形态

- **纯浏览器端转换**：图片不上传服务器（`Next.js` RSC 应用，Canvas 全前端计算）。
- **多品牌官方色卡**：Perler / Artkal / MARD / Hama / Hama Midi / Nabbi / Ikea Pyssla，
  强调「使用每个品牌的**官方色卡**而不是一套通用近似」；MARD 还提供 24/48/72/96/120/144/221/291
  分级色号子集。
- **免费 + PDF/图片导出 + 手动绘制 + 社区图纸库**。

### 1.2 生成器工作流（从生成页 UI 文本还原）

```
上传图片 / 手动绘制（JPG/PNG/WebP ≤10MB）
  → 选「图案细节」风格预设（细节优先 / 精简 / 标准 / 细腻 / 平滑自然）
  → 选图纸宽度（52/104/自定义，单边 ≤200，高度按比例自动算）
  → 选拼豆品牌 + 色号子集（如 MARD 72 色 / 221 色）
  → 可选：在色卡列表里点掉不想要的色号（排除 → 自动重映射）
  → 应用生成设置 → 预览 → 不满意就调参再生成（regenerate 循环）
  → 编辑工具（画笔/橡皮/取色）/ 图层 / 对称轴 / 用量清单 / 导出
```

关键设计：**参数全部收敛成几个「风格预设」**，而不是让用户面对一堆算法名词；
生成后保留「改设置 → 重新生成」闭环，配合「色号排除」做人工兜底。

### 1.3 核心算法管线（从打包产物反推，含具体参数）

在其前端 bundle 里挖到一整套**预设参数表**（每套预设是一组配置），字段如下
（以 `standard` 预设为例，其余差异在括号里）：

```js
{
  id: "standard",                          // 预设 id：simplified/standard/detailed/legacy/zippland…
  maxColors: 10,                           // 色数上限（detailed=16；legacy/zippland=null 不限）
  analysisPixelsPerCell: 4,                // 每格参与统计的像素数（提高每格分析精度）
  minimumForegroundCoverage: .20,          // 前景最少占比，低于则不认为有背景可去
  outlineDarkLuminance: .32,               // 暗轮廓检测：亮度阈值
  outlineDarkRatio: .2,                    // 暗像素占比阈值
  outlineContrast: .16,                    // 轮廓对比度
  outlineWeight: 2.5,                      // 轮廓权重（用于边界保护/边缘处理）
  backgroundSeedDeltaE: 8,                 // 背景「种子」判定阈值（紧）
  backgroundFillDeltaE: 14,                // 背景 flood-fill 传播阈值（松）
  backgroundMinimumConfidence: .85,        // 背景置信度门槛
  cleanupMinimumNeighbors: 5,              // 杂点清理：邻居数门槛（4~7）
  cellSamplingMode: "dominant-bucket",     // 每格采样：dominant-bucket（众数桶）/ average
  colorBucketBits: 4,                      // 众数桶量化位（4~5，16~32 级/通道）
  paletteSelectionMode: "fixed-palette-greedy", // 选色策略：固定色卡贪心 / cluster-then-snap
  colorDistanceMode: "oklab",              // 色差：oklab（默认）/ ciede2000（detailed 用）
  ditheringMode: "none",                   // 抖动：none / floyd-steinberg（detailed 用）
  spatialRegularizationIterations: 2,      // 空间正则化迭代次数（1~2）
  spatialSmoothness: 2,                    // 平滑强度（1~3）
  spatialEdgeSigma: 10                     // 边缘保护 sigma（8~12）
}
```

由此可还原 pixel-beads.com 的完整管线：

```
原图
 ├─① 降采样/解码到分析尺寸（每格 analysisPixelsPerCell 个像素）
 ├─② 每格采样 cellSamplingMode=dominant-bucket：把格内像素按 4~5bit 桶量化，
 │    取频率最高桶的均值色（即「众数优先」，不是全格均值）
 ├─③ 背景检测（在原图像素级，映射前做）：
 │    seedDeltaE=8 找边界种子 → fillDeltaE≈13~14 向外 flood-fill（双阈值，松紧结合）
 │    + minimumForegroundCoverage 把关（前景占比过低就不去背景）
 │    + backgroundMinimumConfidence≈0.85~0.88 置信度门槛
 ├─④ 色卡映射 colorDistanceMode=oklab/ciede2000
 │    paletteSelectionMode=fixed-palette-greedy（直接映射品牌色卡）
 │    或 cluster-then-snap（先对图像聚类出主色，再吸附到色卡最近色）
 ├─⑤ ditheringMode=floyd-steinberg（仅 detailed 预设开）
 ├─⑥ cleanupMinimumNeighbors=4~7：邻域多数表决清理杂点（比「面积阈值」更强）
 ├─⑦ 空间正则化：边缘保护的平滑（iterations=1~2，edgeSigma 保护轮廓不被抹糊）
 ├─⑧ 轮廓处理：outlineDark* 参数对暗色轮廓做加权/保护（治「灰色毛边」）
 ├─⑨ maxColors 贪心削色（standard=10 色、detailed=16 色，默认就压得很狠）
 └─⑩ 色号排除与重映射（用户手动排除的色号自动重映射到最接近的保留色）
```

### 1.4 公开资料印证的关键结论

- 同题项目的作者明确指出（[liangdabiao/perler-beads-ai](https://github.com/liangdabiao/perler-beads-ai/blob/main/CLAUDE.md)）：
  - **「黑色毛边/灰色毛边是因为池化时对 RGB 用了 mean（均值），改为局部 max pooling
    （每格取频率最高的 RGB 值）就好」** —— 与本项目当前用「区域平均色」作映射源的问题完全对应。
  - 杂色问题要靠**连通域 + 颜色相似度 BFS 合并**（把相似连通区域统一成区域主色）。
  - 背景移除要先**定义背景色号列表，从边界 flood-fill**，统计/导出时忽略「外部」格。
  - **色号排除 + 重映射**是「自动去杂不干净」时的标准兜底手段。
- 鸿蒙侧一篇完整链路实践（[ost.51cto.com/posts/50931](https://ost.51cto.com/posts/50931)）补充：
  - 解码限制到最长边 1280px；**最近邻降采样**（取每格中心像素，不用双线性插值，保像素锐边）。
  - **加权 Lab 距离**（亮度/彩度加权）比纯欧氏更接近人眼。
  - **红色主导防御**：对强红像素给非红色卡条目加罚分（红色匹配准确率 92%→99.5%）。
  - 只用到的颜色做调色板裁剪，统计即购物清单。
- 老牌站 [pixel-beads.net](https://www.pixel-beads.net/sites/instruction.html) 的生成流程
  （宽度→色数→品牌→**点掉不要的色号**→选抖动算法→选色差算法→选量化算法→去低频色→导出）
  印证：**「色号排除」与「多算法可选」是这类工具的标准交互**。

## 五、pixel-beads.com 完整算法还原（源码级，2026 补充）

在其前端 Web Worker（`/assets/processing.worker-*.js`）中挖到完整算法实现，
各关键函数还原如下（全部在浏览器内执行，输入为 ≤1024px 分析画布）：

```
输入：分析画布像素（解码后按 analysisPixelsPerCell=4 超采样，单边 ≤200 格）
 │
 ├─ ① 背景检测 Re()【像素级，映射前】
 │    · alpha≤16 视为透明背景
 │    · 取四边像素的 Lab 中位数（re=median）；四角像素中位数作为候选锚点
 │    · 锚点置信度：角点中与锚点 ΔE≤8 的比例 ≥0.75 且角点≥3 → 用角点中位数，否则用边中位数
 │    · 总置信度 C=max(边匹配率, 角点一致率)；C<0.85（auto 模式）→ 放弃去背景
 │    · 从边界 flood-fill，ΔE≤fillDeltaE(13~14) 向内部扩散，标记 mask
 │
 ├─ ② 每格采样 je()【dominant-bucket】
 │    · 重叠面积加权 + alpha 加权聚合（不是简单均值）
 │    · 记录亮度 min/max、暗像素占比、暗像素均值
 │    · 前景覆盖度 = 有效像素权重/格面积；< minimumForegroundCoverage(0.12~0.28) → 该格记 null（背景）
 │    · 轮廓检测：暗像素占比≥outlineDarkRatio 且 (亮度跨度≥outlineContrast 或 平均亮度≤outlineDarkLuminance)
 │      → 该格 isOutline=true，颜色取【暗像素的均值】（这就是治「灰色毛边」的关键：边缘格不再混入亮色）
 │    · 否则取量化桶（colorBucketBits=4~5）中权重最大桶的加权均值
 │
 ├─ ③ 色卡映射（两种策略二选一）
 │    A. fixed-palette-greedy de()：
 │       · 先聚合不同颜色（覆盖度加权，轮廓格 ×outlineWeight）
 │       · He()：贪心选 ≤maxColors 个色卡色，每次选「能覆盖最多未覆盖权重」的色（最大覆盖贪心）
 │       · 每个格子映射到【被选中的色卡色】中距离最近者（OKLab 或 CIEDE2000）
 │       ★ 比「按用量留 top-K」强得多：保留的是最能代表整图的色，色数与色准同时最优
 │    B. cluster-then-snap Ue()：加权 k-means（Lab，12 迭代）聚类出 ≤maxColors 个簇中心
 │       → 吸附到色卡最近色；轮廓格映射到最暗色卡色
 │
 ├─ ④ 抖动 We()：Floyd–Steinberg（RGB 空间、蛇形扫描、误差 clamp 0~255）
 │      跳过背景格与轮廓格（避免边界渗色）
 │
 ├─ ⑤ 空间正则化 ft()：边缘保护平滑，1~2 迭代
 │    · 对每格评估候选色（自己+四邻域色号），代价 = 该格原始 RGB 到候选色的色差
 │      + smoothness×Σ exp(-邻域色差/edgeSigma)（邻域一致则倾向合并）
 │    · 边缘（轮廓格）不参与 → 不会抹糊轮廓
 │
 ├─ ⑥ 杂点清理 ye()：8 邻域多数表决，邻居众数 ≥ cleanupMinimumNeighbors(4~7) 才替换；跳过轮廓格
 │
 └─ ⑦ 诊断 me()：稀有色数（用量≤2）、单格连通域数、背景置信度、平均映射色差等，回传给 UI 展示
```

**额外亮点**：
- **sourceGrid 模式**（用户在裁剪框内生成时）：`lt()` 对每格取「向内缩进 22% 边距」的区域内均值
  —— 刻意避开格子边缘的抗锯齿渗色，从源头消除「背景沿主体轮廓渗一圈」的 halo。
- **生成方法预设**（`ht()`）：fast/dominant/average/soft/pixel-detail 对应不同参数组合，
  与「图案细节」风格（简化/标准/细腻/平滑自然）构成双层预设。
- **UI 信息透明**：把背景置信度、使用色数、平均映射色差（meanMappingDistance）、稀有色数、
  单格区域数等诊断数据直接展示给用户，并给出「生成设置已应用」的状态反馈。
- 色卡支持按色号点击**排除/恢复**，排除后自动重映射；支持用户直接输入自定义 hex 覆盖色。
- **镜像翻转**：为熨烫时「摆反图、烫正图」提供一键翻转（国内小程序「拼豆制图师」也有此功能）。

## 二、本项目现状与问题根因

### 2.1 色差（颜色对不上 / 发灰 / 毛边）根因

| # | 根因 | 现状代码 | 影响 |
|---|------|----------|------|
| C1 | **映射源用了「区域均值」而非「众数」** | `pattern_converter.dart:136-139` 用 `sampled.avgColors` 作映射源；`sampler.dart` 算出的 `colors`（众数桶均值）**在转换链路里根本没被用到** | 网格内边缘像素/背景像素被平均进主色 → 颜色发灰、发脏、出现「毛边」，色相漂移。这是与 pixel-beads「dominant-bucket」最直接的差距 |
| C2 | **色卡数据非官方/无版本标注** | `mard_221/291`（社区整理）、`perler.json`/`hama.json`（maxcleme/beadcolors 社区实测）；README 自认「屏幕色与实物豆存在色差」 | 数据本身与实物/官方色有偏差，映射得再准也是「对不准的色卡」 |
| C3 | **只有 CIEDE2000 一种色差，且无加权/无特殊色防御** | `color_mapper.dart`（KD-tree 候选 + ΔE00 终选） | 无 OKLab 快速感知距离选项；无亮度/彩度加权；无红色主导防御 → 特定色相（红/肤色/蓝）容易选错 |
| C4 | **抖动默认开 + 抖动时关闭杂色合并** | `pattern_converter.dart:143-177`（dither 时 `minBlockSize=1`） | 照片渐变 OK，但**主体与背景交界处抖动出大量「中间色」颗粒**，既添杂色又让边界发灰 |
| C5 | **导出/预览色彩管理缺失** | `export_screen.dart` 直接按 sRGB 值画 PNG/PDF | 屏幕色域/伽马差异放大「色差」感知（次要） |

### 2.2 背景被识别成拼豆 根因

| # | 根因 | 现状代码 | 影响 |
|---|------|----------|------|
| B1 | **背景移除发生在「映射之后」、且用单一紧阈值** | `post_processor.dart:_removeBackground` 在色号矩阵上 flood-fill，`backgroundDeltaE=4.0` 固定 | 背景渐变/多色调背景映射成多个色号，彼此 ΔE>4 → 只去掉最贴边的一圈，其余全留成豆子 |
| B2 | **无双阈值（seed/fill）** | 边界每个种子各自 `ΔE<4` 传播 | 找不到「紧找种子、松传播」的两级容错，复杂背景覆盖不全 |
| B3 | **无前景覆盖率/置信度把关** | 无 `minimumForegroundCoverage`、无 `backgroundMinimumConfidence` | 主体铺满画面时边界种子会「淹进」主体相似色区域，把主体边缘挖掉 |
| B4 | **背景种子只有「当前格一个颜色」，无背景色列表** | 每种子用自己的 lab 判断 | 多色背景（如天空+草+围栏）需要多个背景色锚点 |
| B5 | **背景判定在「色卡映射后」的色号空间做** | 同上 | 背景两色映射到同一色号还行，映射到不同色号就漏；**在源图像素级（OKLab/CIEDE2000）做更稳** |
| B6 | **抖动叠加** | 见 C4 | 边界抖动颗粒映射成背景附近色号，正好卡在 ΔE=4 之外 → 背景沿主体轮廓「渗一圈」 |

> 另外 v0.5 的 `subject_detector.dart`（裁剪页自动提取主体）只负责给出裁剪框，
> 与转换链路的背景移除**是两套独立逻辑**，后者没有复用前者的背景色聚类结果。

## 三、修改方案

总体思路：**把 pixel-beads 的管线参数化地移植进纯 Dart 核心，保持本地优先/无依赖原则；
用预设收敛参数；用双阈值 + 前置背景检测治背景；用众数采样 + 官方色卡治色差。**

### P0-1 采样源切换：众数桶优先（治 C1，改动小收益大）

- `sampler.dart`：现有 `colors`（众数桶均值）就是 pixel-beads 的 `dominant-bucket`（bit=3，即 8 级/通道，
  对应其 4~5bit 的稍粗/稍细档）。保持输出两个数组不动。
- `pattern_converter.dart:136-139`：映射源从 `sampled.avgColors` 改为 `sampled.colors`（众数色）；
  `avgColors` 仅保留给「原图对比」视图用（`ConvertResult.avgColors` 语义不变）。
- 新增 `SamplerOptions.cellSamplingMode: 'dominant-bucket' | 'average'`（默认 dominant-bucket，
  legacy 模式保留 average 供对比），`colorBucketBits` 可配（默认 3）。
- 验收：纯色像素画无毛边；照片主体色更鲜；灰度渐变图边界不再发灰。

### P0-2 背景移除重写：映射前、双阈值、带把关（治 B1~B6，核心改动）

新增 `lib/core/background_remover.dart`（在**源图像素级**工作，映射前执行）：

1. **背景色聚类**（复用 `subject_detector.dart` 的 `_dominantColors` 思路，抽成公共函数）：
   从四边采样像素 → 众数聚类出 1~3 个背景候选色（OKLab/CIEDE2000）。
2. **双阈值 flood-fill**：边界种子用 `seedDeltaE≈8`（紧）确认背景色，之后向邻域用
   `fillDeltaE≈13`（松）传播；背景候选色命中任一个即标记。
3. **把关**：`minimumForegroundCoverage=0.15`（非背景占比 <15% 就不去背景，防误删主体）；
   `backgroundMinimumConfidence=0.85`（背景像素占比过低则放弃）。
4. **映射前把背景格标为 -1**（跳过色卡映射与 BOM 统计），同时**保留映射后兜底**：
   `post_processor._removeBackground` 的阈值改为可配（默认从 4 提到 8）并支持色号列表模式，
   作为「前置检测失败」时的次级防线。
5. `ConvertOptions` 增补：`backgroundSeedDeltaE` / `backgroundFillDeltaE` /
   `minimumForegroundCoverage` / `backgroundColors`(手动指定背景色，可选)。
6. 预览页给「去背景」加**蒙层预览**：在「原图对比」视图里把将被移除的格子画成棋盘格/半透明，
   让用户一眼看到哪些会被去掉（治「背景被识别成豆子」的直观感知）。

验收：10 张简单背景图（纯色/渐变/双色背景各若干）背景移除成功率 ≥90%；
主体铺满图不误删；渐变背景不再残留一圈背景豆。

### P0-3 色差距离增强（治 C3）

- 新增 `lib/core/oklab.dart`：OKLab 转换 + 距离（快速感知距离，作为默认距离选项，
  CIEDE2000 保留给「细腻」档）。映射接口抽象为 `ColorDistance`（oklab | ciede2000）。
- `color_mapper.dart`：候选收集与终选共用所选距离；`candidateCount` 提一档（64→96）并
  加**加权距离选项**（亮度/彩度加权，参考 51cto 方案）；加**红色主导防御**：
  对强红像素（`L>30 且 a*>50 且 C≈a*`）给非红卡条目按 G/B 值加罚分。
- `ConvertOptions.colorDistanceMode` 可配（默认 oklab，UI 高级参数里暴露：感知最快/最准两档）。

### P0-4 杂点清理与边界保护（治 C4 + 毛边）

- `post_processor.dart` 新增**多数表决清理**（pixel-beads 的 `cleanupMinimumNeighbors=4~5`）：
  对每格统计 3×3 邻域内同色数量，`< 阈值` 的格子换成邻域众数色（迭代 1~2 次），
  替代/补充当前「仅面积阈值合并」；抖动开启时也不再完全跳过清理，而是用轻档（neighbors=3）。
- 新增**边缘保护的空间正则化**（`spatialSmoothness/edgeSigma`）：多数表决只在
  邻域颜色接近（ΔE < edgeSigma）时合并，避免把主体轮廓抹糊。
- `minBlockSize` 保留但语义调整为「先多数表决、再面积合并」。
