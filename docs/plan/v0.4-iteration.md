## 01 为什么这样迭代（承接需求洞察与竞品分析）

回顾 v0.3 的两份分析：

- **需求洞察**：P0=色号准/出图快不中断，P1=数字填色/套盒库存匹配，P2=社区/AI。
- **竞品对比**：我们的护城河是「本地优先 + CIEDE2000 精准算法」；竞品的软肋是「色差」（被吐槽最多）与「像素画创作工具不顺手」；颂拼豆的强项是「套盒匹配」。

**v0.4 的定位**：不再扩功能面，做「留存型功能 + 信任加固」，顺序为——

1. **补闭环**：跟做进度持久化（拼一半能续）、参数记忆接线（偏好真正生效）。
2. **差异化留存**：库存/套盒匹配 MVP（攻击颂拼豆强项，落在我们本地优先的技术底子上）。
3. **信任护城河**：实物校色管线（攻击竞品被吐槽最多的「色差」，直接对应 R2 风险）。

## 02 本轮落地内容

| # | 功能 | 实现 | 价值 |
|---|------|------|------|
| 1 | 跟做进度持久化 | `craft_progress_store.dart`：FNV-1a 内容指纹 + JSON 存储；`craft_screen` 打开时加载、打勾时保存 | 数字填色从"演示"变"可续拼的核心闭环" |
| 2 | 参数记忆接线 | `AppSettings` 默认值对齐（dither=true、maxColors=0）；`setImage` 读设置初始化；`setup_screen` 持久化板型/参数；设置页默认板型含"自定义" | 用户偏好下次自动生效，历史债清零 |
| 3 | 库存/套盒匹配 MVP | `inventory.dart`（`computeMissing`）+ `inventory_store.dart` + `inventoryProvider` + `inventory_screen`（管理页）+ 预览缺豆清单横幅/弹层 | 生成后立即知道"缺哪几色、缺几颗" |
| 4 | 实物校色管线 | `tools/calibrate_palette.py`：CSV/JSON 实测色 → 批量更新色卡 rgb/hex | 色卡数据从"社区屏幕色"升级为"实物实测"的工具基础 |

### 关键设计决策

- **跟做进度用「内容指纹」而非作品 id**：同一图纸（同色卡+同尺寸+同网格）得到相同指纹，无论是否已保存为作品，进度都能跨重启恢复；避免"未保存就拼"丢进度。
- **参数记忆对齐 v0.3 默认值**：`AppSettings.dither` 默认改为 `true`、`maxColors` 默认改为 `0`，避免接线后把 v0.3 的"抖动默认开、色数不限"回退掉。
- **库存 MVP 分两步**：v0.4 先做「缺豆提醒」；v0.4.1 落地「按库存过滤色卡映射」——`ColorMapper.allowedIndices` 掩码 + `setup`「只用手头有的豆子」开关，返回原色号下标保证渲染一致。

## 05 下一步（v0.4.1 / v0.5 候选）

按投入产出排序：

1. **「按库存过滤色卡」映射**（v0.4.1 ✅ 已落地）：`ColorMapper` 支持 `allowedIndices` 掩码，`setup` 加「只用手头有的豆子」开关，生成时只从拥有的色号做最近邻映射。
2. **跟做进度可视化升级**（✅ 已落地）：图例每色迷你进度条 + 完成态（绿色编号徽章 +「✅ 完成」），顶部进度区新增「完成 X/K 色」汇总与「全部完成」提示。
3. **实物校色执行**：采购 MARD/Perler 实样 → 标准光照拍照取色 → `tools/calibrate_palette.py` 更新色卡 → 对比盲测。
4. **埋点**：转换完成率/导出率/次日留存（上架前必须，需选型轻量方案）。
5. **分享回流**：导出 PNG/PDF 加"豆图出品"品牌水印与回流引导。
6. **社区 / AI**：仍延后（需后端或质量存疑）。

## 06 风险登记（v0.4 增量）

| 风险 | 对策 |
|------|------|
| 参数记忆接线后，用户旧设置（dither=false）与新默认不一致 | `fromJson` 对旧字段带默认值兜底；缺失字段按新默认 |
| 库存数据与色卡更新不同步（色卡改版后色号对不上） | 库存按 `paletteId + code` 存储，缺失色号在管理页自然不显示、不报错 |
| 跟做进度指纹随算法改动而变化（进度"失效"） | 指纹基于最终网格内容，与算法无关；仅图纸内容变化才失效，符合直觉 |
| 库存管理页 221 色列表较长 | 提供"只看已录入"过滤；后续可加搜索 |
